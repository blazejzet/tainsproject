Under the hood

Trains Project 3 is a from-scratch rebuild in Swift 6: one multiplatform SwiftUI + SpriteKit app for iPadOS 26 and macOS 26, with almost all code in a local Swift package called TrainsKit. The authoritative design lives in 3.0/DESIGN.md.

Repository layout

  App/                       @main, app icon, InfoPlist strings

  Packages/TrainsKit/        the local Swift package with all the code

The bundle identifier is pl.zyglarski.trainsproject2 and the iCloud container is iCloud.pl.zyglarski.trainsproject2. Both are shared with the 2.0 port; iCloud is not used in v1.

Architecture

TrainsKit is split into six modules with a strict dependency direction. The model and the engine know nothing about SpriteKit or SwiftUI.

ModuleResponsibilityKey files
TrainsModelThe Codable program model, the block catalogue as data, values and conditions, validation, the editing API used for undo, and the AI generation seam.Program.swift, Catalog.swift, Values.swift, Editing.swift, Validation.swift, Generation.swift
TrainsEngineThe interpreter: runners, threads, the fixed 60 Hz scheduler, events. Talks to the world only through the WorldAdapter protocol, so it runs headless in tests.Engine.swift, Engine+Scheduler.swift, Engine+Blocks.swift, Engine+Actions.swift, Engine+Events.swift, TrainThread.swift
TrainsStageThe SpriteKit StageScene that implements the world: sprites, physics bodies and joints, contacts, the pen, bubbles, the variable HUD, effects, design-mode editing, touch/mouse/keyboard/tilt input.StageScene+World.swift, World/StagePhysics.swift, World/ContactTracker.swift, Design/, Input/
TrainsArtThe 32-colour palette, costume and background catalogues, palette-swap colour variants, the code-drawn locomotive, wagons, mascot and glyphs, and the pixel font.Art.swift, Glyphs.swift, Shells*.swift, PixelFont.swift
TrainsAudioAudioDirector: synthesised effects (square, triangle, noise) and the music decks that crossfade playlists per screen, on a dedicated audio queue.Audio.swift, ChipSynth.swift, SoundRecipes.swift, MusicPlaylist.swift
TrainsUISwiftUI: the home screen, the workspace (swap / side by side), the dock, inspector, settings, gamepad, the code editor (canvas, layout, drag & drop, depot, popovers) and the project store.Shell/, Editor/, Shared/WorkspaceModel.swift, Shared/ProjectStore.swift

Data flow

  • Editing. Every edit goes through WorkspaceModel.edit { project in … }. It copies the project, applies the change through the TrainsModel editing API (insert, uncouple, setArg, moveTrain…), pushes the old value on the undo stack (max 100), refreshes the stage’s design view and schedules an autosave one second later. Edits are ignored while running.
  • Running. WorkspaceModel.run() saves, then StageScene.run(project) switches the scene to live mode and calls Engine.start(project). Each frame the scene calls engine.advance(by: dt). The engine drives the world through WorldAdapter, and the scene feeds taps, input and contacts back with engine.handle(_:).
  • Highlighting. The engine is @Observable. After each step it republishes activeBlocks and activeTrains per runner, assigning them only when they change. The editor unions them over the selected character’s runners.

Build and test

xcode-select may point at the Command Line Tools, so set DEVELOPER_DIR first.

export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer

# Unit tests for the model, engine and audio (macOS, fast)
cd 3.0/Packages/TrainsKit && swift test

# The app
xcodebuild -scheme TrainsProject -destination 'platform=macOS' build
xcodebuild -scheme TrainsProject -destination 'generic/platform=iOS Simulator' build

# A scripted UI run with screenshots. Taps and drags use window fractions (0…1).
Tools/ui_steps.sh /tmp/shots "wait:4;tap:0.255,0.40;wait:3;shot:workspace"
  • The unit tests cover the model, editing and validation, the engine (blocks, events, values, scheduling) against a MockWorld, and the audio playlists.
  • The UI test runner understands tap:x,y, hold:x,y,sec, drag:x1,y1,x2,y2, swipeleft, wait:sec, shot:name and dump. XCUITest’s idle waiting is disabled because the game animates constantly. The app is terminated at the end so its music stops.
  • DEBUG builds accept -UITestOpenProject "<name>" to open a project on launch.

Save format

Each project is one pretty-printed JSON file at Application Support/Projects/<uuid>.json, with ISO 8601 dates and sorted keys. There is no document browser. The schema is versioned with schemaVersion (currently 1).

Actorid, name, costume, variant (0–7), hearts, mass, body, placements, trains

Trainid, trigger {kind, args}, blocks, canvasX, canvasY
Blockid, kind, args, body, optional elseBody (only on if)

Valuenumber, random(min,max), variable, property, timer

Block kinds and parameter names are stable string identifiers (the ids on the Blocks page). Enums with associated values use Swift’s synthesised Codable form ("_0" keys). An excerpt from a real file, a Say wagon:

{
  "args" : {
    "seconds" : { "value" : { "_0" : { "number" : { "_0" : 2 } } } },
    "text" : { "text" : { "_0" : "Hi!" } }
  },
  "body" : [ ],
  "id" : "DA70AD65-5810-40C8-8B0D-33EB0AD75D06",
  "kind" : "say"
}

When a character is deleted, Validator.sanitized repairs other trains that pointed at it, replacing invalid arguments with their catalogue defaults.

The block catalogue

The language is data. TriggerKind.spec and BlockKind.spec return a BlockSpec with category, parameters (ParamSpec: name, kind, default, and an optional visibleWhen rule), whether the block is a container, and a one-line summary. This single table drives:

  • the editor’s depot, plates and popovers;
  • the defaults of new wagons (Block.make(kind));
  • validation of loaded and generated programs;
  • the AI prompt (CatalogDescription.text).

To add a wagon: add a case to BlockKind with its spec, execute it in Engine+Blocks.swift or Engine+Actions.swift, add its glyph in TrainsArt/Glyphs.swift and its names in EditorNames.swift and Editor.xcstrings (English and Polish), then cover it with an engine test.

AI track builder (prepared)

v1 ships the seam for an on-device generator based on Apple’s Foundation Models, but not the generator itself:

public protocol ProgramGenerator: Sendable {
    /// Trains for `context.actor` that do what `description` says. Implementations must return
    /// trains that pass `Validator` (use `Validator.sanitized` as the last step).
    func generate(description: String, context: GenerationContext) async throws -> [Train]
}

CatalogDescription.text renders the whole language into a compact prompt. It begins:

LOCOMOTIVES (a train starts with exactly one):
- start: When the run starts.
- tap: When this character is tapped during the run.
- input(key: left|right|up|down|a|b): When a gamepad button or key is pressed.
…
MOTION WAGONS:
- move(direction: forward|backward|up|down|left|right, tiles: number 0...16 tiles, speed: slow|normal|fast): Glide a number of tiles in a direction.
…
World: 16x16 tiles, x 0-15 left to right, y 0-15 bottom to top. Angles: 0 = right, 90 = up.

Art pipeline

  1. Generate. Codex image generation renders each costume and themed background from a prompt kept in Art/prompts/. Raw outputs go to Art/raw/.
  2. Pixelize. Tools/process-art.sh runs Tools/pixelize.swift, which snaps every image to a true pixel grid (32 × 32 characters, 256 × 256 backgrounds) and to the fixed palette by dominant colour, and writes it into TrainsArt/Resources.
  3. Review. Tools/render-gallery.sh renders Art/contact-sheet.png. With a second argument it also dumps every glyph, wagon, costume variant and background as a 1× PNG. The art on this website was exported that way.

The locomotive, wagon shells, mascot, app icon, the dusk and grid backgrounds and all wagon glyphs are drawn in code on the palette. Tools/render-gallery.sh --icon regenerates the app icon. Colour variants are palette swaps at run time.

The palette

Every pixel in the app uses these 32 colours (PICO-8 plus its extension). Pen colours are chosen by index.

Category colours are palette entries: events 8, motion 12, looks 13, control 9, physics 11, data 10.

Music

The soundtrack in new-vibe/ is Opus inside .m4a, which AVFoundation cannot decode. Each track is converted to AAC into 3.0/Art/music/ and bundled in TrainsAudio/Resources:

ffmpeg -i START.m4a -c:a aac -b:a 160k start.m4a
SceneTracksPlays
HomestartLooping on the home screen
Codingcoding_1, coding_2, coding_3In turn, looping, while editing
Runninggame_1, game_2In turn, looping, while a program runs
Win / Losewin / failOnce at the end of a run, then straight into the coding loop

Two music decks crossfade between scenes, and the music ducks under sound effects. Going back to coding after a jingle does not restart the coding loop. Music on/off and effects on/off are stored in UserDefaults.

Localisation

Strings live in String Catalogs: Shell.xcstrings for the app shell, Editor.xcstrings for wagon, parameter and option names, and InfoPlist.xcstrings. English is the development language and Polish is complete. Sample projects and character names are localised when they are created.
